\chapter{Deep Learning Architectures for Semantic Segmentation}
\label{cap:architectures}

Semantic segmentation classifies each pixel of an image according to the class of the object it belongs to. Different objects of the same class are not distinguished~\cite[Chapter~12]{geron2026handson}. In this thesis, the class used for navigation is the path between the crop rows. All the classes are listed in Chapter~\ref{cap:dataset_training}.

This chapter describes the three segmentation networks compared in Chapter~\ref{cap:dataset_training} (FCN, DeepLabV3, and LR-ASPP with a MobileNetV3-Large backbone) and SAM~3, which generated the labels of the networks trained without manual annotation, including the network that runs on the robot. Section~\ref{sec:seg_formulation} introduces the concepts shared by the three networks.

\section{Principles of segmentation networks}
\label{sec:seg_formulation}

For each pixel, a segmentation network outputs one score for each class. These scores are called logits, and the softmax function converts them into the estimated probabilities of the classes. The predicted class of the pixel is the one with the highest probability. The network is trained by minimizing the cross entropy, which penalizes the model when it estimates a low probability for the target class~\cite[Chapter~4]{geron2026handson}. Each pixel is treated as one instance, as in Long et al., whose loss is a sum of per-pixel terms over the output~\cite[Sections~3 and~4]{long2015fcn}. Chapter~\ref{cap:dataset_training} adds a weight for each class to this loss (Section~\ref{subsec:c4_training_config}).

A classification network reduces the spatial resolution of its feature maps with layers of stride greater than 1. Chen et al.\ call \textit{output stride} the ratio of the input image resolution to the resolution of the final output. In the classification networks they consider, it is 32~\cite[Section~3.1]{chen2017deeplab}. At this resolution, a network may recognize that an object is in a region of the image without locating its boundaries precisely~\cite[Chapter~12]{geron2026handson}. The networks of this chapter use two ways to recover spatial detail:
\begin{itemize}
    \item \textbf{Atrous (dilated) convolution.} An atrous convolution with rate $r$ is equivalent to a convolution with a filter in which $r-1$ zeros are inserted between consecutive filter values. To obtain an output stride of 16 instead of 32, Chen et al.\ set to 1 the stride of the last layer that reduces the resolution and replace the following convolutions with atrous convolutions of rate 2. The feature maps become denser without extra parameters~\cite[Section~3.1]{chen2017deeplab}. DeepLabV3 and the TorchVision backbones of FCN and LR-ASPP use atrous convolution.
    \item \textbf{Features from lower layers.} In the encoder-decoder structure, the encoder gradually reduces the spatial size of the feature maps, and the decoder gradually recovers the object details and the spatial size~\cite[Section~2]{chen2017deeplab}. The original FCN (Section~\ref{subsec:fcn_original}) and LR-ASPP (Section~\ref{subsec:lraspp_arch}) add predictions or features from lower, finer layers to the coarse ones.
\end{itemize}

In the TorchVision v0.20.1 implementations used in this thesis, each network has a \textit{backbone}, a classification network without its final layers, which extracts the feature maps, and a \textit{segmentation head}, which computes the logits from them. The logits are then resized to the input resolution with bilinear interpolation~\cite{torchvision_fcn,torchvision_deeplabv3,torchvision_lraspp}.

\section{Fully Convolutional Networks (FCN)}
\label{sec:fcn_arch}

\subsection{Original architecture}
\label{subsec:fcn_original}

Long et al.\ view the fully connected layers of a classification network as convolutions whose kernels cover their entire input region. The resulting network accepts inputs of any size and outputs a map of class scores~\cite[Section~3.1]{long2015fcn}. With the VGG-16 classifier, this map has a stride of 32, which limits the detail of the upsampled output~\cite[Section~4.2]{long2015fcn}. Long et al.\ therefore combine the final prediction layer with lower layers of finer stride (Figure~\ref{fig:fcn_architecture}):
\begin{itemize}
    \item \textbf{FCN-32s} upsamples the stride-32 predictions to the image resolution in one step.
    \item \textbf{FCN-16s} adds a $1\times1$ convolution on the stride-16 layer \texttt{pool4} to produce additional class predictions. It sums them with the stride-32 predictions upsampled by 2, and upsamples the result to the image.
    \item \textbf{FCN-8s} repeats the same step with the stride-8 layer \texttt{pool3}.
\end{itemize}
The upsampling layers are transposed convolutions, also called deconvolutions. The $2\times$ upsampling layers are initialized to bilinear interpolation and then learned~\cite[Sections~3.3 and~4.2]{long2015fcn}.

\subsection{TorchVision implementation}
\label{subsec:fcn_torchvision}

The \texttt{fcn\_resnet50} model of TorchVision does not use the skip architecture. Its backbone is ResNet-50~\cite{he2016deep}, whose residual blocks add the input of the block to the output of its layers through a shortcut connection. In the bottleneck blocks of ResNet-50, a $1\times1$ convolution reduces the number of channels, a $3\times3$ convolution works on the reduced channels, and a second $1\times1$ convolution restores them~\cite[Sections~3.2 and~4.1]{he2016deep}. ResNet-50 has four stages, \texttt{layer1} to \texttt{layer4} in TorchVision. TorchVision replaces the stride of \texttt{layer3} and \texttt{layer4} with atrous convolutions, so the backbone has an output stride of 8 instead of 32~\cite{torchvision_fcn}.

The segmentation head, \texttt{FCNHead}, takes the 2048 channels of \texttt{layer4}. It applies a $3\times3$ convolution to 512 channels, batch normalization, ReLU, dropout with probability 0.1, and a $1\times1$ convolution that gives the logits. A second \texttt{FCNHead}, the auxiliary classifier, takes the 1024 channels of \texttt{layer3}. Its output enters only the training loss (Section~\ref{subsec:c4_training_config})~\cite{torchvision_fcn}.

\section{DeepLabV3}
\label{sec:deeplabv3_arch}

\subsection{Atrous Spatial Pyramid Pooling}
\label{subsec:aspp_module}

DeepLabV3 applies atrous convolution in the last blocks of a ResNet and adds an Atrous Spatial Pyramid Pooling (ASPP) module on the resulting feature map~\cite[Section~3]{chen2017deeplab}. ASPP applies atrous convolutions with different rates in parallel to the same feature map, so that the features are resampled at several scales. As the rate grows, fewer filter weights fall on the feature map and more on the padding zeros. With a rate close to the size of the feature map, a $3\times3$ filter acts as a $1\times1$ filter. To add global context, ASPP therefore also includes image-level features, obtained by global average pooling, a $1\times1$ convolution, and bilinear upsampling. The module has five branches, all with 256 filters and batch normalization:
\begin{itemize}
    \item one $1\times1$ convolution,
    \item three $3\times3$ atrous convolutions with rates 6, 12, and 18 at output stride 16, doubled at output stride 8,
    \item the image-level features.
\end{itemize}
The outputs of the five branches are concatenated and pass through a $1\times1$ convolution with 256 filters, followed by the final $1\times1$ convolution that gives the logits~\cite[Section~3.3]{chen2017deeplab}. Figure~\ref{fig:deeplabv3_aspp} shows the module. Block1 to Block4 in the figure are the four ResNet stages (\texttt{layer1} to \texttt{layer4} in TorchVision).

\subsection{TorchVision implementation}
\label{subsec:deeplabv3_torchvision}

The \texttt{deeplabv3\_resnet50} model of TorchVision uses the same backbone as \texttt{fcn\_resnet50}, the ResNet-50 with output stride 8 (Section~\ref{subsec:fcn_torchvision}). Its ASPP rates are 12, 24, and 36, the rates of Chen et al.\ for output stride 8. The $1\times1$ projection of the concatenated branches is followed by batch normalization, ReLU, and dropout with probability 0.5. A $3\times3$ convolution with 256 channels, batch normalization, and ReLU follow, and a $1\times1$ convolution gives the logits. Like FCN, the model has an auxiliary \texttt{FCNHead} on \texttt{layer3}, whose output enters only the training loss~\cite{torchvision_deeplabv3}.

\section{MobileNetV3 and LR-ASPP}
\label{sec:mobilenet_lraspp}

Howard et al.\ designed MobileNetV3 for mobile phone CPUs, with a network architecture search that takes into account the latency of each candidate model~\cite[Abstract and Section~4.1]{howard2019mobilenetv3}. They released two versions, MobileNetV3-Large and MobileNetV3-Small, for high and low resource use cases~\cite[Sections~1 and~5.4]{howard2019mobilenetv3}. This thesis uses the Large version. Together with MobileNetV3, they proposed the Lite Reduced ASPP (LR-ASPP) segmentation head~\cite[Section~6.4]{howard2019mobilenetv3}.

\subsection{MobileNetV3-Large backbone}
\label{subsec:mobilenetv3_backbone}

The blocks of MobileNetV3 combine layers introduced by earlier networks~\cite[Section~3]{howard2019mobilenetv3}:
\begin{itemize}
    \item \textbf{Depthwise separable convolution.} A light depthwise convolution applies a single spatial filter to each input channel, and a heavier $1\times1$ pointwise convolution combines the channels to generate new features~\cite[Section~3]{howard2019mobilenetv3}, \cite[Chapter~12]{geron2026handson}.
    \item \textbf{Inverted residual with linear bottleneck.} A $1\times1$ convolution expands the channels, a depthwise convolution works in the expanded space, and a $1\times1$ projection reduces the channels again. The input and output of the block are narrow and have no nonlinearity. The residual connection is used only when the input and output have the same number of channels. This is the opposite of the ResNet bottleneck of Section~\ref{subsec:fcn_torchvision}, which first reduces and then restores the channels.
    \item \textbf{Squeeze-and-excitation (SE).} In some of the blocks, an SE module is placed after the depthwise convolution, so it acts on the expanded representation~\cite[Section~3 and Table~1]{howard2019mobilenetv3}. An SE module applies global average pooling to obtain one value per channel, compresses these values in a small layer with ReLU, and computes with a second layer one weight between 0 and 1 per channel. The channels are then multiplied by these weights~\cite[Chapter~12]{geron2026handson}. In MobileNetV3, the small layer has 1/4 of the channels of the expansion layer~\cite[Section~5.3]{howard2019mobilenetv3}.
\end{itemize}
Figure~\ref{fig:mobilenetv3_block} shows the resulting block. MobileNetV3 also replaces the sigmoid and the swish nonlinearity with piecewise-linear \textit{hard} versions built on ReLU6. Howard et al.\ found no discernible difference in accuracy, and the hard versions are cheaper to compute on mobile devices. The hard swish is used only in the second half of the network~\cite[Section~5.2]{howard2019mobilenetv3}.

\subsection{LR-ASPP head}
\label{subsec:lraspp_arch}

LR-ASPP derives from R-ASPP, a reduced version of ASPP (Section~\ref{subsec:aspp_module}) that keeps only two branches, a $1\times1$ convolution and global average pooling. In LR-ASPP, the pooling branch works like an SE module and contains only one $1\times1$ convolution. Atrous convolution in the last block of MobileNetV3 gives denser features, and a skip connection from low-level features adds detail~\cite[Section~6.4]{howard2019mobilenetv3}. Figure~\ref{fig:lraspp_head} shows the head.

In the TorchVision model \texttt{lraspp\_mobilenet\_v3\_large}, the last stage of the backbone uses atrous convolution, so its last layer, with 960 channels, has output stride 16 instead of 32. The low-level features are the 40 channels of the backbone at output stride 8. The head works as follows~\cite{torchvision_lraspp,torchvision_mobilenetv3}:
\begin{enumerate}
    \item A $1\times1$ convolution with batch normalization and ReLU reduces the 960 channels to 128.
    \item A second branch applies global average pooling to the 960 channels, a $1\times1$ convolution to 128 channels, and a sigmoid. It gives one weight per channel.
    \item The output of the first branch is multiplied channel by channel by these weights and upsampled with bilinear interpolation to the size of the low-level features.
    \item Two $1\times1$ convolutions compute logits from this result and from the low-level features, and the two logit maps are summed.
\end{enumerate}
Unlike Figure~\ref{fig:lraspp_head}, which uses a $49\times49$ pooling kernel, TorchVision pools over the whole feature map.

\section{SAM~3}
\label{sec:sam3_theory}

SAM~3 (Section~\ref{sec:dataset_annotation}) consists of a detector for images and a tracker with a memory for videos. Both take vision-language inputs from a shared Perception Encoder (PE) backbone~\cite[Section~3]{carion2026sam3}. Figure~\ref{fig:sam3_architecture} shows the architecture. The labels of this thesis were generated from text prompts on single images, so only the detector is used.

The detector follows the DETR paradigm, in which a set of learned object queries proposes the objects. PE encodes the image and the text prompt. A fusion encoder conditions the image embeddings on the prompt tokens through cross-attention. In the decoder, the object queries cross-attend to the conditioned image embeddings, and each query predicts whether its object corresponds to the prompt, together with a box and a mask. A learned global token, the presence token, predicts only whether the concept is present in the image. Each query then only has to locate its object, and its final score is the product of its own score and the presence score~\cite[Section~3]{carion2026sam3}.

SAM~3 has about 850 million parameters, of which about 450 million are in the vision encoder and 300 million in the text encoder~\cite[Appendix~C.1]{carion2026sam3}. Its reported time of 30~ms for one image refers to an NVIDIA H200 data-center GPU~\cite[Section~1]{carion2026sam3}. SAM~3 was therefore run offline (Section~\ref{subsec:c4_sam_annotation}). The robot runs an LR-ASPP network trained on its labels (Section~\ref{subsec:c4_deployed_network}).
