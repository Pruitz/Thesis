\chapter{Deep Learning Architectures for Semantic Segmentation}
\label{cap:architectures}

Semantic segmentation classifies each pixel of an image according to the class of the object it belongs to~\cite{geron2026handson}. In this thesis, the robot follows the path between the crop rows, so the path is the class used for navigation.

This chapter describes FCN, DeepLabV3, and LR-ASPP, the three segmentation networks compared in Chapter~\ref{cap:dataset_training}, and SAM~3, used to label training images automatically. Section~\ref{sec:seg_formulation} introduces the concepts used by the three networks.

\section{Principles of segmentation networks}
\label{sec:seg_formulation}

\subsection{Convolutional networks for segmentation}
\label{subsec:seg_networks}

For each pixel, a semantic segmentation network outputs one score for each class. These scores are called logits, and the softmax function converts them into the estimated probabilities of the classes. The predicted class of the pixel is the one with the highest probability. During training, a loss function measures the error of the output, and backpropagation and gradient descent update the parameters to reduce it~\cite{geron2026handson}.

A convolutional neural network (CNN) is built mainly from convolutional layers. Each neuron of a convolutional layer looks only at a small region of the input, for example $3\times3$ pixels. It multiplies each value of the region by a weight and sums the results. The grid of these weights is a filter, also called a kernel. The layer has several filters and outputs one channel for each filter. All the neurons of a channel share the same filter, so it recognizes a pattern, such as a line, in any position of the image. The filters are learned during training. The first layers detect small low-level features and the following layers combine them into larger ones. In a \textit{classification network}, the resolution decreases and the number of channels grows as the image goes through the layers. At the end, a few fully connected layers estimate the class of the whole image~\cite{geron2026handson}.

A \textit{semantic segmentation network} outputs one class for each pixel of the image, and not one for the whole image. A simple approach turns a classification network into a fully convolutional network, that is, a network without fully connected layers. It keeps the first part of the classification network, which reduces the resolution. In place of the fully connected layers, it has convolutional layers, which compute the class scores at the reduced resolution. Upsampling then increases the resolution until it is the same as that of the input image. The outputs of lower layers, which have a higher resolution, can also be added during the upsampling to recover part of the spatial detail lost in the first part~\cite{geron2026handson}.

The TorchVision v0.21.0 implementations of FCN, DeepLabV3, and LR-ASPP used in this thesis (Sections~\ref{sec:fcn_arch}--\ref{sec:mobilenet_lraspp}) consist of two main parts. The \textit{backbone}, a classification network without its final layers, extracts the features. The \textit{segmentation head}, made mainly of convolutional layers, computes the logits from them at 1/8 of the input resolution. The logits are then resized to the input resolution with bilinear interpolation~\cite{torchvision_fcn,torchvision_deeplabv3,torchvision_lraspp,torchvision_seg_utils}. For example, with $K$ classes and the $224\times224$ input image used on the robot (Section~\ref{subsubsec:control_node}), the logits are a $K\times28\times28$ map, which is resized to $K\times224\times224$.

\subsection{ResNet-50 and atrous convolution}
\label{subsec:resnet_atrous}

ResNet-50 is the backbone of the FCN and DeepLabV3 models used in this thesis. Adding more layers to an already deep network can increase its training error. He et al.\ call this the degradation problem and address it with residual blocks~\cite{he2016deep}.

ResNet-50 is built mainly from residual blocks. A residual block is a group of convolutional layers whose input is added, channel by channel, to their output (Figure~\ref{fig:bottleneck}). The connection that carries the input to this sum is called a shortcut connection. The layers therefore learn only the difference between the desired output and the input. In their experiments, residual networks are easier to optimize than plain networks with the same layers~\cite{he2016deep}.

\begin{figure}[H]
  \centering
  \input{images/architectures/bottleneck_tikz}%
  \caption{Bottleneck block of ResNet-50. The input is added to the output of the three convolutions. Batch normalization and ReLU are not shown. Based on He et~al.~\cite{he2016deep}.}
  \label{fig:bottleneck}
\end{figure}

ResNet-50 uses a type of residual block called a bottleneck block, which has three convolutions. In Figure~\ref{fig:bottleneck}, the input has 256 channels. A $1\times1$ convolution reduces them to 64, a $3\times3$ convolution works on these 64 channels, and a second $1\times1$ convolution brings them back to 256. The input of the block is then added to this output~\cite{he2016deep}. When a block changes the number of channels or the size of the feature map, the input cannot be added directly, so a $1\times1$ convolution on the shortcut connection first brings it to the same dimensions~\cite{he2016deep}.

ResNet-50 has four stages of residual blocks. The first convolution and a max pooling layer, both with stride 2, reduce the height and width of the input to 1/4. The first block of the second, third, and fourth stages halves them again with a stride of 2, so the height and width of the final feature map are 32 times smaller than those of the input~\cite{he2016deep}.

An atrous (dilated) convolution applies its filter to input values that are spaced apart, which is equivalent to inserting zeros between the values of the filter. It covers a larger area of the input with the same number of parameters~\cite{geron2026handson,chen2017deeplab}. Removing the downsampling of the last layers of a network and using atrous convolutions there gives denser feature maps~\cite{chen2017deeplab}. The ratio between the resolution of the input image and that of the final feature map is called the \textit{output stride}~\cite{chen2017deeplab}.

\section{Fully Convolutional Network (FCN)}
\label{sec:fcn_arch}

\subsection{Original architecture}
\label{subsec:fcn_original}

Long et al.\ introduce fully convolutional networks (FCNs) for semantic segmentation~\cite{long2015fcn,geron2026handson}. They define an FCN as a network with only layers that operate on local input regions, such as convolution, pooling, and activation functions, so it works on inputs of any size. Some earlier networks already worked on inputs of any size, and Long et al.\ place them in this class. They state that, to their knowledge, they are the first to train FCNs end-to-end for pixelwise prediction and from supervised pre-training~\cite{long2015fcn}. In the rest of this thesis, FCN without a suffix indicates the \texttt{fcn\_resnet50} model of TorchVision (Section~\ref{subsec:fcn_torchvision}), which is based on this work.

Long et al.\ turn the classification network VGG-16 into a fully convolutional network. They remove its last fully connected layer, which gives the scores of the classes of the original task, and convert the other fully connected layers into convolutional layers. A new $1\times1$ convolution gives one coarse score map for each segmentation class, 32 times smaller than the input image (stride 32)~\cite{long2015fcn}.

Upsampling these maps directly would limit the detail of the output. The best model of Long et al., FCN-8s, uses learned upsampling layers to combine them with class scores from two lower layers, \texttt{pool4} and \texttt{pool3}, which have a higher resolution. The combined map is 8 times smaller than the input image (stride 8), and a final bilinear upsampling brings it to the input resolution. The output has one score for each class and each pixel~\cite{long2015fcn}.

\subsection{TorchVision implementation}
\label{subsec:fcn_torchvision}

The \texttt{fcn\_resnet50} model of TorchVision consists of a modified ResNet-50 backbone and a head, \texttt{FCNHead}, plus an auxiliary head described below~\cite{torchvision_fcn}. The four stages of the backbone are \texttt{layer1} to \texttt{layer4} (Figure~\ref{fig:resnet50}). \texttt{layer3} and \texttt{layer4} do not reduce the size of the feature maps and use atrous convolutions with rates 2 and 4 from their second block, so the output stride is 8 instead of 32~\cite{torchvision_fcn,torchvision_resnet}. For a $224\times224$ input, the final feature maps are therefore $28\times28$ instead of the $7\times7$ of the original ResNet-50~\cite{he2016deep}.

\begin{figure}[!htb]
  \centering
  \resizebox{\linewidth}{!}{\input{images/architectures/resnet50_tikz}}%
  \caption{The modified ResNet-50 of TorchVision, used as the backbone of the FCN and DeepLabV3 models. Each stage is a sequence of bottleneck blocks. The channels are those at the output of each box. The dark orange stages, \texttt{layer3} and \texttt{layer4}, use atrous convolutions instead of a stride of 2, with rates 2 and 4 from their second block. Below each box are the output stride (OS) and the height and width of the feature maps for a $224\times224$ input. The final average pooling and fully connected layer are removed. Based on He et~al.~\cite{he2016deep} and TorchVision~\cite{torchvision_resnet,torchvision_fcn}.}
  \label{fig:resnet50}
\end{figure}

For a $224\times224$ input, the backbone outputs $2048\times28\times28$ feature maps (Figure~\ref{fig:resnet50}). \texttt{FCNHead} applies a $3\times3$ convolution with 512 filters and then a $1\times1$ convolution with one filter for each of the $K$ classes, which gives the $K\times28\times28$ logits. A second \texttt{FCNHead}, the auxiliary classifier, works in the same way on the $1024\times28\times28$ output of \texttt{layer3}, with 256 filters in its $3\times3$ convolution. It is used only in the loss, not in the prediction (Section~\ref{subsec:c4_training_config})~\cite{torchvision_fcn,torchvision_seg_utils}.

Unlike FCN-8s, the model does not combine class scores from lower layers and has no learned upsampling. Its logits are resized with a single bilinear interpolation~\cite{long2015fcn,torchvision_fcn,torchvision_seg_utils}.

\section{DeepLabV3}
\label{sec:deeplabv3_arch}

DeepLabV3, proposed by Chen et al., addresses two problems of semantic segmentation: the reduced resolution of the feature maps and objects that appear at different scales~\cite{chen2017deeplab}. It uses atrous convolution (Section~\ref{subsec:resnet_atrous}) for the first problem and an Atrous Spatial Pyramid Pooling (ASPP) module for the second.

\subsection{Atrous Spatial Pyramid Pooling}
\label{subsec:aspp_module}

ASPP applies atrous convolutions with different rates in parallel to the same feature map. Each branch covers a region of a different size, so the module captures information at several scales~\cite{chen2017deeplab}.

As the rate grows, fewer filter weights fall on the feature map and more on the padding zeros. With a rate close to the size of the feature map, a $3\times3$ filter acts as a $1\times1$ filter. To overcome this problem and incorporate global context, Chen et al.\ add an image pooling branch to ASPP, in parallel with the other branches. This branch applies global average pooling, which gives one value per channel, then a $1\times1$ convolution, and bilinear upsampling back to the size of the feature map~\cite{chen2017deeplab,geron2026handson}. Its output can then be concatenated with those of the other branches.

In the model of Chen et al., ASPP has five branches, all with 256 filters and batch normalization: one $1\times1$ convolution, three $3\times3$ atrous convolutions with rates 6, 12, and 18 at output stride 16 (doubled at output stride 8), and the image pooling branch. The five outputs are concatenated and pass through a $1\times1$ convolution with 256 filters~\cite{chen2017deeplab}. The right side of Figure~\ref{fig:deeplabv3_aspp} shows the module: the $1\times1$ convolution, the three atrous convolutions, the image pooling branch, and the concatenation followed by a $1\times1$ convolution.

  \caption{DeepLabV3 with the ASPP module at output stride 16: block3 does not reduce the feature map, block4 uses atrous convolution with rate 2, and the ASPP rates are 6, 12, and 18. \subsection{Original architecture}
\label{subsec:deeplabv3_original}

Chen et al.\ describe their framework as applicable to any network and implement it on a ResNet~\cite{chen2017deeplab}. They set to 1 the stride of the layers that would reduce the resolution at the end of the network and replace the following convolutions with atrous convolutions. For output stride 8, these are the two layers that would reduce the feature maps from 1/8 to 1/16 and from 1/16 to 1/32, and the last two stages use rates 2 and 4~\cite{chen2017deeplab}. ASPP is applied to the resulting feature map, and a final $1\times1$ convolution gives the logits, which are upsampled to the input resolution~\cite{chen2017deeplab}. Figure~\ref{fig:deeplabv3_aspp} shows the whole architecture at output stride 16. Block1 to Block4 in the figure are the four ResNet stages (\texttt{layer1} to \texttt{layer4} in TorchVision).

\subsection{TorchVision implementation}
\label{subsec:deeplabv3_torchvision}

The \texttt{deeplabv3\_resnet50} model of TorchVision uses the same backbone architecture as \texttt{fcn\_resnet50}, with output stride 8 (Section~\ref{subsec:fcn_torchvision}), followed by the ASPP module of Section~\ref{subsec:aspp_module} with rates 12, 24, and 36~\cite{torchvision_deeplabv3}. These are the rates of Chen et al.\ for output stride 8~\cite{chen2017deeplab}. Figure~\ref{fig:heads} shows the head, from the output of the backbone to the final output. Unlike the model of Chen et al., the TorchVision model has a $3\times3$ convolution after ASPP~\cite{chen2017deeplab,torchvision_deeplabv3}. Like FCN, it has an auxiliary \texttt{FCNHead} on \texttt{layer3}, used only in the loss, not in the prediction (Section~\ref{subsec:c4_training_config})~\cite{torchvision_deeplabv3}.

\section{MobileNetV3 and LR-ASPP}
\label{sec:mobilenet_lraspp}

Howard et al.\ designed MobileNetV3 for mobile phone CPUs~\cite{howard2019mobilenetv3}. This thesis uses the Large version, MobileNetV3-Large. Together with MobileNetV3, they proposed the LR-ASPP segmentation head~\cite{howard2019mobilenetv3}.

\subsection{MobileNetV3 block}
\label{subsec:mobilenetv3_block}

The MobileNetV3 block is an inverted residual block, which first expands and then reduces the channels, the opposite of the ResNet bottleneck of Section~\ref{subsec:resnet_atrous}. A $1\times1$ convolution expands them. A depthwise convolution applies a single spatial filter to each channel separately, so the number of channels does not change. A $1\times1$ projection then reduces the channels~\cite{howard2019mobilenetv3,geron2026handson}. The residual connection is used only when the input and output have the same number of channels~\cite{howard2019mobilenetv3}. In some of the blocks, a squeeze-and-excitation (SE) module after the depthwise convolution applies global average pooling and computes one weight between 0 and 1 per channel, and the channels are multiplied by these weights~\cite{howard2019mobilenetv3,geron2026handson}. Figure~\ref{fig:mobilenetv3_block} shows the resulting block.

\subsection{Original architecture}
\label{subsec:lraspp_arch}

For semantic segmentation, Howard et al.\ use MobileNetV3-Large as a backbone. It starts with a convolution with stride 2, followed by 15 of these blocks. They apply atrous convolution to the last stage of the backbone, so the output stride is 16~\cite{howard2019mobilenetv3}.

The Lite Reduced ASPP (LR-ASPP) head has two branches instead of the five of ASPP (Section~\ref{subsec:aspp_module}). In Figure~\ref{fig:lraspp_original}, the features at 1/16 of the input resolution enter both. The upper branch is a $1\times1$ convolution with 128 filters. The lower branch works like an SE module: a $49\times49$ average pooling with a large stride, one $1\times1$ convolution, a sigmoid, and a bilinear upsampling. The outputs of the two branches are multiplied and upsampled to 1/8 of the input resolution, and a $1\times1$ convolution gives one channel for each class. A skip connection takes the low-level features at 1/8, and another $1\times1$ convolution gives one channel for each class from them. The two results are summed~\cite{howard2019mobilenetv3}.

\subsection{TorchVision implementation}
\label{subsec:lraspp_torchvision}

The \texttt{lraspp\_mobilenet\_v3\_large} model of TorchVision has the same structure as the model of Howard et al.\ (Section~\ref{subsec:lraspp_arch}). The last stage of the backbone (Figure~\ref{fig:mobilenetv3_backbone}) uses atrous convolution with rate 2. The head takes the high-level features with 960 channels at output stride 16 and the low-level features with 40 channels at output stride 8~\cite{torchvision_lraspp,torchvision_mobilenetv3}. Figure~\ref{fig:heads} shows the head, from the outputs of the backbone to the final output. Unlike the model of Howard et al., the TorchVision model pools over the whole feature map instead of using a $49\times49$ pooling kernel, so each channel has a single weight for the whole feature map and the pooling branch needs no bilinear upsampling~\cite{howard2019mobilenetv3,torchvision_lraspp}.

\section{Segmentation heads}
\label{sec:segmentation_heads}

Figure~\ref{fig:heads} compares the heads of the three TorchVision models described in Sections~\ref{subsec:fcn_torchvision}, \ref{subsec:deeplabv3_torchvision}, and \ref{subsec:lraspp_torchvision}. All three compute the logits at 1/8 of the input resolution and resize them with bilinear interpolation. FCN has a single path of two convolutions. In DeepLabV3, ASPP processes the same feature map in five parallel branches and concatenates their outputs. LR-ASPP processes the high-level and the low-level features separately and sums the results~\cite{torchvision_fcn,torchvision_deeplabv3,torchvision_lraspp,torchvision_seg_utils}.

\section{SAM~3}
\label{sec:sam3_theory}

SAM~3 segments all the instances of a concept, given for example as a short text prompt. It consists of a detector for images and a tracker with a memory for videos. Both use the same image encoder, part of the Perception Encoder (PE) backbone~\cite{carion2026sam3}. Figure~\ref{fig:sam3_architecture} shows the architecture. The labels of this thesis were generated from text prompts on single images, so only the text encoder, the image encoder, and the detector are used. The image exemplars, the visual prompts, the tracker, and its memory are not used.

In this thesis, each text prompt is processed separately on each image. PE encodes the image and the text prompt. The Detector block of Figure~\ref{fig:sam3_architecture} contains a fusion encoder and a decoder. The fusion encoder conditions the image features on the prompt, so the same image has different features for different prompts. The decoder starts from a set of learned object queries. Each query looks for one object in the conditioned features and predicts a box and a score of how well the object corresponds to the prompt. A segmentation head then uses the query and the conditioned features to compute the mask of the object~\cite{carion2026sam3}. The output is one mask with its score for each instance found.

\begin{figure}[H]
  \centering
  \includegraphics[width=0.9\linewidth]{images/architectures/sam3_architecture.png}
  \caption{SAM~3 architecture. The detector segments the instances of the prompted concept in each image, and the tracker propagates the masks between video frames. The tracker and the memory bank are not used in this thesis. Reproduced from Carion et~al.~\cite{carion2026sam3}.}
  \label{fig:sam3_architecture}
\end{figure}

SAM~3 has about 850 million parameters~\cite{carion2026sam3}, against about 3.2 million of LR-ASPP~\cite{torchvision_lraspp}. It was run offline to generate the training labels (Section~\ref{subsec:c4_sam_annotation}), and the robot runs an LR-ASPP network trained on these labels (Section~\ref{subsec:c4_deployed_network}).
