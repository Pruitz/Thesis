\chapter{Dataset Preparation and Comparative Model Training}
\label{cap:segmentation}
\label{cap:dataset_training}

This chapter describes the datasets and two experiments on the segmentation network. The first compares FCN, DeepLabV3, and LR-ASPP, fine-tuned from pretrained weights on a manually annotated lettuce dataset, and selects LR-ASPP for the robot. Manual annotation was done only for lettuce, because it is time-consuming. The second experiment tests whether LR-ASPP networks trained on masks generated by SAM~3, without manual correction, can replace manual annotation. The binary labeling was then extended to all crops, and a network trained on this collection is the one deployed on the robot (Section~\ref{subsec:c4_deployed_network}).

\subsection{Semantic classes and labeling targets}
\label{subsec:c4_semantic_classes}

The segmentation labels in this thesis use up to four semantic classes: background, plants, path (the traversable corridor between two crop rows), and covering material (plastic mulch film). The manual lettuce annotations use all four classes (Section~\ref{subsec:c4_lettuce}).

The labels generated with SAM~3 (Section~\ref{subsec:c4_sam_annotation}) follow three configurations, each used to train a separate network:
\begin{itemize}
\item \textbf{Four-class configuration:} background, plants, path, and covering material, matching the four classes of the manual lettuce annotations.
\item \textbf{Three-class configuration:} background, plants, and path. No prompt targets the covering material.
\item \textbf{Binary configuration:} background and path. This configuration is used both for the lettuce-only binary network and for the multi-crop dataset.
\end{itemize}
For row following, the path mask is the input of the geometric extraction in Chapter~\ref{cap:geometric_reference}.

\section{Dataset preparation}
\label{sec:c4_datasets}

\subsection{Lettuce dataset with manual annotation}
\label{subsec:c4_lettuce}

The manually annotated lettuce dataset, \texttt{Data}, contains 762 image--mask pairs from eight folders, with masks prepared from the manual annotations in \texttt{annotations.json}. These masks are the ground truth for all the evaluations of this chapter. They contain four classes (background, plants, path, and covering material), and the path class marks only the corridor the robot should follow, not other visible paths. The SAM~3 labels of the same images form the datasets \texttt{Data\_insalataSAM\_4class}, \texttt{Data\_insalataSAM\_3class}, and \texttt{Data\_insalataSAM\_2class} (Section~\ref{subsec:c4_sam_annotation}).

\subsection{Automated zero-shot annotation via SAM~3}
\label{subsec:c4_sam_annotation}

Manual segmentation takes a lot of human work, so this experiment tests whether SAM~3 can replace it. SAM~3 was run offline with text prompts, and its masks were used for training without inspection, filtering, or correction. Manual masks were available for lettuce and were more accurate, but the unedited masks were kept on purpose, to measure how well a network performs when the annotation is fully automatic.

All autolabel masks were generated using \texttt{SAM3SemanticPredictor} with the local \texttt{sam3.pt} checkpoint and a confidence threshold of 0.25. For each text prompt, SAM~3 returned zero or more candidate masks, and pixels with mask values greater than 0.5 were assigned to the corresponding class. When masks of different prompts overlapped, the class was assigned according to a fixed prompt order, listed below for each dataset: later prompts were written only on pixels still labeled as background, so earlier classes were never overwritten. Pixels not assigned by any prompt remained background. The prompts and their order are:
\begin{itemize}
    \item \texttt{Data\_insalataSAM\_4class} (lettuce images): \texttt{plants} (class 1), then \texttt{plastic mulch film} (class 3), then \texttt{central farm path} (class 2)
    \item \texttt{Data\_insalataSAM\_3class} (lettuce images): \texttt{plants} (class 1), then \texttt{central farm path} (class 2)
    \item \texttt{Data\_insalataSAM\_2class} (lettuce images): \texttt{central farm path} only (class 1)
    \item \texttt{Data\_allPlantsSAM2} (images of lettuce, tomato, and cucumber crops): \texttt{central path} only (class 1).
\end{itemize}
The SAM~3 masks are not compared directly with the manual annotations. Their quality enters the evaluation only through the networks trained on them (Section~\ref{subsec:c4_supervision_configurations}).

\subsection{Tomato and cucumber images}
\label{subsec:c4_tomato_cucumber}

The tomato and cucumber images were labeled only by SAM~3 and are used only in the multi-crop dataset \texttt{Data\_allPlantsSAM2}, on which the binary network deployed on the robot is trained. They have no manual ground truth, so they are not part of the quantitative evaluations of Section~\ref{sec:c4_supervision_comparison}.

\subsection{Dataset partitioning}
\label{subsec:c4_dataset_splits}

The lettuce networks use a random 80/10/10 split of the 762 pairs: 609 training, 76 validation, and 77 test images. The training split updates the weights, the validation split gives the loss at the end of each epoch and selects the best checkpoint, and the test split is used only for the final scores. The three SAM~3 lettuce datasets contain the same 762 images in the same order and use the same split file as the manual model, so the 77 test images are the same for all four lettuce networks and none of them is used for training. For the multi-crop network evaluated in Section~\ref{subsec:c4_deployed_network}, the 77 lettuce test images were removed from \texttt{Data\_allPlantsSAM2}, and the remaining 1882 of 1959 pairs were split 80/10/10.

The split is random at the level of single images. Each lettuce folder is one video recorded along a different path and contributes images to both the training and the test split, so the networks are trained on other photos of the same paths as the test images. The IoU values may therefore overestimate the performance on new paths or fields. This applies to all the networks of the comparison.

The realistic scenario uses only the 42 test images of \texttt{insalata\_grande1}, \texttt{insalata\_grande2}, and \texttt{insalata\_media1}. These folders were recorded between parallel rows, where the robot operates, from viewpoints the robot can reach. The other five folders were recorded from viewpoints the robot cannot reach and can show more than one path, while the manual masks label only the path the robot should follow. The realistic scenario is a subset of the test split, not a separate test set.

\section{Architecture comparison: FCN, DeepLabV3, and LR-ASPP}
\label{sec:c4_architecture_comparison}

\subsection{Model selection and pretrained weights}
\label{subsec:c4_model_selection}

FCN, DeepLabV3, and LR-ASPP were chosen among the implementations available in TorchVision, for practical reasons and not after a comparison with every available architecture. Each network has a backbone, which extracts image features, and a segmentation head, which gives the class scores. All three start from pretrained parameters, and only their output layers are adapted to the target classes.

For FCN and DeepLabV3, the selected implementations use a ResNet-50
backbone with pretrained segmentation weights. After these weights
are loaded, the final convolution of the main classifier is replaced by
a new $1\times1$ convolution with one output channel per target class
(4 channels). The final convolution of the auxiliary classifier is
replaced in the same way.

LR-ASPP is initialized in the same way. The implementation loads the
default pretrained weights of the complete LR-ASPP model with a
MobileNetV3-Large backbone. Its segmentation head ends with two
$1\times1$ convolutions, one applied to the low-level features and one
to the high-level features~\cite{torchvision_lraspp}. Both are replaced
by new convolutions with 4 output channels. LR-ASPP has no auxiliary
classifier.

The default weights of the three models were trained on a subset of
COCO restricted to the 20 categories of Pascal VOC~\cite{torchvision_fcn,torchvision_deeplabv3,torchvision_lraspp}.
All three networks therefore start from pretrained segmentation weights
of the same origin, and only their final output convolutions are newly
initialized.

\subsection{Training configuration and loss formulation}
\label{subsec:c4_training_config}

\subsubsection{Loss function and class weighting}
To keep the classes with many pixels from dominating the training, the models use a weighted cross-entropy loss $\mathcal{L}_{\text{WCE}}$, in which each pixel is multiplied by the weight $w_c$ of its ground-truth class $c$. The weights are computed on the training split only. With $N_c$ the number of pixels of class $c$ in all the training masks and $C$ the number of classes (four in this comparison),
\begin{equation}
    \text{inv}_c = \frac{\sum_{j=0}^{C-1} N_j}{C \cdot N_c}, \qquad w_c = \frac{\text{inv}_c}{\frac{1}{C}\sum_{j=0}^{C-1} \text{inv}_j}.
    \label{eq:class_weights_norm}
\end{equation}
A rare class receives a large weight and a frequent class a small one, and the weights have mean 1.

For FCN and DeepLabV3, which incorporate an auxiliary classifier on the \texttt{layer3} features (output stride 8 in the dilated TorchVision backbone), the total training objective combines the primary and auxiliary losses with an auxiliary weighting factor of $0.4$:
\begin{equation}
    \mathcal{L}_{\text{total}} = \mathcal{L}_{\text{WCE}}(\text{main}) + 0.4 \cdot \mathcal{L}_{\text{WCE}}(\text{aux}).
    \label{eq:total_training_loss}
\end{equation}
For LR-ASPP, which lacks an auxiliary head, training relies solely on the primary loss $\mathcal{L}_{\text{WCE}}(\text{main})$.

\subsubsection{Data augmentation and two-stage optimization}
Data augmentation is applied only to the training subset: random horizontal flips with probability 0.5, random rotations between $-30^\circ$ and $30^\circ$, and, with probability 0.8, a color jitter of brightness and contrast (factors in $[0.8, 1.2]$) and saturation (factors in $[0.85, 1.15]$) to handle variable outdoor illumination. The validation and test sets are not augmented. Images are not resized, and all images are normalized with the ImageNet mean and standard deviation.

The networks were trained on an NVIDIA GeForce RTX 2080 SUPER with 8~GB of memory, with a batch size of 2.

Optimization proceeds across $200$ epochs in two distinct phases:
\begin{enumerate}
    \item \textbf{Stage 1 (Warmup, Epochs 1--10):} Backbone parameters are frozen by setting \texttt{requires\_grad = False}. Only the segmentation heads (and auxiliary classifiers when present) are optimized using AdamW with an initial learning rate of $10^{-3}$ and weight decay of $10^{-4}$. A cosine-annealing scheduler with $T_{\text{max}} = 200$ and $\eta_{\text{min}} = 10^{-6}$ updates the learning rate after each epoch. In the first epochs, the newly initialized output layers make large errors, and the resulting large gradients could damage the pretrained weights. Freezing the reused layers during these epochs gives the new layers time to learn reasonable weights~\cite[Chapter~11]{geron2026handson}.
    \item \textbf{Stage 2 (Differential Fine-Tuning, Epochs 11--200):} At epoch 10, the backbone is unfrozen. A new AdamW optimizer is instantiated with decoupled parameter groups: the backbone is assigned a learning rate of $10^{-5}$ and the segmentation heads a learning rate of $10^{-4}$. The lower learning rate of the unfrozen backbone limits changes to its pretrained weights~\cite[Chapter~11]{geron2026handson}. The cosine-annealing scheduler is re-initialized across the remaining 190 epochs ($T_{\text{max}} = 190, \eta_{\text{min}} = 10^{-6}$).
\end{enumerate}

Early stopping was not used: all three networks were trained for the full 200 epochs, so that the complete training and validation loss curves could be recorded. After each epoch, the model is evaluated on the unaugmented validation set. The weights are saved whenever the validation loss falls below its previous minimum, and the weights of the final epoch are saved separately.

\subsection{Evaluation metrics and results}
\label{subsec:c4_architecture_results}

The three networks are evaluated on the 77 test images with the intersection over union of each class $c$,
\begin{equation}
    \text{IoU}_c = \frac{\text{TP}_c}{\text{TP}_c + \text{FP}_c + \text{FN}_c},
    \label{eq:eval_iou}
\end{equation}
where $\text{TP}_c$, $\text{FP}_c$, and $\text{FN}_c$ are the true positive, false positive, and false negative pixels of class $c$. The mIoU is the mean over the four classes, background included. The inference time is measured on the training GPU, not on the robot (Section~\ref{subsec:timing}), one image at a time at its original resolution, and covers the forward pass and the argmax. The epoch column of Table~\ref{tab:c4_architecture_results} gives the epoch with the lowest validation loss, whose weights are evaluated.

FCN and DeepLabV3 reach the same mIoU (0.9253), 1.08 percentage points
above LR-ASPP, and LR-ASPP has the lowest IoU in every class
(Table~\ref{tab:c4_architecture_class_iou}). LR-ASPP is 7.2 times faster
than FCN and 10.6 times faster than DeepLabV3.

For FCN and DeepLabV3, the validation loss reaches its minimum early
(Figure~\ref{fig:training_loss_curves}). After that, both networks start
to overfit, and their validation loss rises while the training loss
keeps decreasing. For LR-ASPP, the validation loss reaches a plateau
around epoch 75 and does not rise until epoch 200. The losses of FCN and
DeepLabV3 include the auxiliary term of
Eq.~\eqref{eq:total_training_loss}, while those of LR-ASPP do not, so
the absolute values are not comparable across networks.

\subsection{Selection of LR-ASPP}
\label{subsec:c4_lraspp_selection}

LR-ASPP was selected for its speed. Its mIoU is 1.08 percentage points below that of FCN and DeepLabV3, but it is 7 to 11 times faster. The SAM~3-supervised networks of the next section therefore all use LR-ASPP.

The SAM~3-supervised networks reach their minimum validation loss much earlier than the manual baseline, between epochs 18 and 38 against epoch 162. A possible explanation, not verified in this work, is the noise of the SAM~3 labels, which are also the labels of their validation split. Arpit et al.~\cite{arpit2017memorization} observed that a network trained with partly random labels first learns the patterns shared by the real data and only then fits the noisy labels, so its validation accuracy reaches its maximum before the training accuracy becomes high. Their labels were randomly corrupted, while the SAM~3 errors depend on the prompts and on the scene, so their result is only an analogy.

    \item \textbf{Complete test set (77 images):} all eight lettuce folders, including viewpoints that the robot cannot reach.
    \item \textbf{Realistic scenario (42 images):} the test images of the three folders recorded between parallel rows (Section~\ref{subsec:c4_dataset_splits}).
\end{itemize}

In the four-class network, the IoU of the covering material and of the background is low. Visual inspection of the SAM~3 masks showed that SAM~3 segmented the covering material poorly in general and also assigned the greenhouse plastic cover to this class, which is background in the manual masks. With an mIoU of 0.5925 in the realistic scenario, against 0.9113 for the manual baseline, the four-class SAM~3 labels do not replace manual annotation when all four classes are needed.

All SAM~3-supervised networks lose much of their path accuracy on the complete test set (path IoU 0.39--0.41), while the manual model does not (0.9532). The drop comes from the five folders outside the operational scenario, whose images were taken from viewpoints the robot cannot reach. In these images the manual masks label only the path the robot should follow. Visual inspection showed that the SAM~3 path labels also cover other parts of the ground, such as adjacent paths and soil outside the corridor, especially where the path between the rows is not clearly visible. The networks learn this wider path class, and the IoU counts the additional ground pixels as false positives. The complete-test values therefore combine segmentation errors and this difference between the SAM~3 and manual labels. The two effects were not separated quantitatively.

In the realistic scenario, the path IoU of the three SAM~3-supervised networks is between 0.8966 and 0.9013, 5.7 to 6.2 percentage points below the manual baseline (0.9587). The three SAM~3-supervised networks differ from each other by less than 0.5 percentage points, so these data do not show that removing the plant and covering material classes improves path segmentation. The geometric extraction uses only the path class (Chapter~\ref{cap:geometric_reference}), so the binary configuration was chosen for the robot. Whether its accuracy is sufficient for row following is assessed in the offline and field tests of Chapter~\ref{cap:experiments}.

\subsection{Extension to the multi-crop dataset and deployed network}
\label{subsec:c4_deployed_network}

After the lettuce study, the binary labeling was extended to the complete image collection, with images of lettuce, tomato, and cucumber crops, labeled entirely by SAM~3 with the \texttt{central path} prompt and without manual correction. The binary LR-ASPP network trained on this collection is the one deployed on the robot and used in the following chapters (Chapters~\ref{cap:platform} and~\ref{cap:experiments}).

The training data of the deployed network include the lettuce test images, so its IoU on them would not be an independent measure. A second network with the same configuration was therefore trained on the collection without these images (Table~\ref{tab:c4_results_binary_general}). Its results estimate the accuracy of the configuration, not of the exact deployed weights. On the complete test set it is clearly better than the lettuce-only binary network (0.6369 against 0.3917).
