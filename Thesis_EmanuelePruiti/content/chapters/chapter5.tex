\chapter{Dataset Preparation and Comparative Model Training}
\label{cap:segmentation}
\label{cap:dataset_training}

Following the theoretical analysis of deep learning architectures in Chapter~\ref{cap:architectures}, this chapter describes the datasets, annotation pipelines, and experimental model evaluations that guide the configuration for robotic integration.

The experimental study began by fine-tuning FCN, DeepLabV3, and LR-ASPP from pretrained weights on a manually annotated lettuce dataset for an empirical comparison. Because manual segmentation was time-consuming, this initial training was limited to lettuce rather than repeated across every target crop. Its outcome led to the adoption of LR-ASPP for embedded deployment.

After the selection of LR-ASPP, the second experiment investigated whether a network trained only on masks generated automatically by SAM~3, without manual filtering or correction, segments the navigable path accurately enough for row following. The manually annotated lettuce dataset was available and more accurate, but the aim was to test labels that require no human correction at all. The comparison models were trained on lettuce images only, the crop with manual ground truth: SAM~3 produced a four-class label set (background, plants, path, covering material), a three-class set (background, plants, path), and a binary set (background, path), and one LR-ASPP network was trained on each. These three networks are evaluated by comparing their predictions with the manual lettuce masks; the SAM~3 masks themselves are not compared with the manual annotations. After this study, the binary labeling was extended to the complete image collection, labeled entirely by SAM~3 (\texttt{Data\_allPlantsSAM2}), and the network trained on it is the one deployed on the robot. To evaluate this general configuration on the same lettuce test images, a further network was trained with the same labels after removing those test images from the collection.

This chapter details image acquisition, dataset partitioning, training parameters, and offline benchmark evaluations. Subsequent chapters detail geometric navigation extraction and closed-loop robot validation.

\subsection{Semantic classes and labeling targets}
\label{subsec:c5_semantic_classes}

The segmentation labels in this thesis use up to four semantic classes: background, plants, path (the traversable corridor between two crop rows), and covering material (plastic mulch film). The manual lettuce annotations use all four classes (Section~\ref{subsec:c5_lettuce}).

The labels generated with SAM~3 (Section~\ref{subsec:c5_sam_annotation}) follow three configurations, each used to train a separate network:
\begin{itemize}
\item \textbf{Four-class configuration:} background, plants, path, and covering material, matching the four classes of the manual lettuce annotations.
\item \textbf{Three-class configuration:} background, plants, and path. No prompt targets the covering material.
\item \textbf{Binary configuration:} background and path. This configuration is used both for the lettuce-only binary network and for the general dataset \texttt{Data\_allPlantsSAM2}. For row following, the path mask is the input of the geometric extraction in Chapter~\ref{cap:geometric_reference}.
\end{itemize}

\section{Dataset preparation}
\label{sec:c5_datasets}

\subsection{Lettuce dataset with manual annotation}
\label{subsec:c5_lettuce}

The manually annotated lettuce dataset, identified as \texttt{Data},
contains 762 image--mask pairs distributed across eight folders. Its
masks were prepared from the manual annotations stored in
\texttt{annotations.json}. The same manual reference is used for the
initial architecture comparison and for evaluating the models trained
with SAM~3-generated labels. These manual masks are the ground truth for
all evaluations in this chapter. They contain four classes (background,
plants, path, and covering material), and the path class marks only the
corridor the robot should follow, not other visible paths. The three lettuce autolabel datasets
(\texttt{Data\_insalataSAM\_4class}, \texttt{Data\_insalataSAM\_3class},
and \texttt{Data\_insalataSAM\_2class}) contain images from the same eight
lettuce folders, with masks generated by SAM~3 instead of the manual
annotations.

\subsection{Automated zero-shot annotation via SAM~3}
\label{subsec:c5_sam_annotation}

Manual segmentation requires substantial human effort, which motivated testing whether SAM~3 can replace it. SAM~3 was run offline with text prompts, and the generated masks were used without manual filtering, cleaning, or polygon correction. Keeping the imperfect masks was an intentional choice: although the manual lettuce masks were available and more accurate, the experiment measures how well a network trained on unedited autolabels performs, and therefore whether the manual annotation step can be removed. Correcting the SAM~3 masks would likely improve the trained networks, as the higher accuracy of the network trained on manual masks suggests, but it would reintroduce manual work; this trade-off was not evaluated.

All autolabel masks were generated using \texttt{SAM3SemanticPredictor} with the local \texttt{sam3.pt} checkpoint and a confidence threshold of 0.25. For each text prompt, SAM~3 returned zero or more candidate masks, and pixels with mask values greater than 0.5 were assigned to the corresponding class. When masks of different prompts overlapped, the class was assigned according to a fixed prompt order, listed below for each dataset: later prompts were written only on pixels still labeled as background, so earlier classes were never overwritten. Pixels not assigned by any prompt remained background. The prompts and their order are:
\begin{itemize}
    \item \texttt{Data\_insalataSAM\_4class}: \texttt{plants} (class 1), then \texttt{plastic mulch film} (class 3), then \texttt{central farm path} (class 2);
    \item \texttt{Data\_insalataSAM\_3class}: \texttt{plants} (class 1), then \texttt{central farm path} (class 2);
    \item \texttt{Data\_insalataSAM\_2class}: \texttt{central farm path} only (class 1);
    \item \texttt{Data\_allPlantsSAM2}: \texttt{central path} only (class 1).
\end{itemize}
The SAM~3 masks are not compared directly with the manual annotations. Their quality enters the evaluation only through the networks trained on them (Section~\ref{subsec:c5_supervision_configurations}).

\subsection{Tomato and cucumber images}
\label{subsec:c5_tomato_cucumber}

In addition to lettuce, the image collection includes tomato and cucumber crops. These images were annotated exclusively with SAM~3 and are included only in the multi-crop dataset (\texttt{Data\_allPlantsSAM2}) used to train the general binary network deployed on the robot. They were not included in the training sets of the lettuce-specific models.

Because no manual ground truth was created for tomato and cucumber, these crops are not part of the quantitative evaluations in Section~\ref{sec:c5_supervision_comparison}. Similarly, the initial comparison among architectures (FCN, DeepLabV3, and LR-ASPP) was carried out exclusively on the lettuce dataset.

\subsection{Dataset partitioning}
\label{subsec:c5_dataset_splits}

The lettuce training runs use an 80\% training, 10\% validation, and
10\% test partition. The training and validation counts are
the integer parts of 80\% and 10\%, while the remaining samples form the
test split. For the 762 image--mask pairs, this yields 609 training, 76 validation, and 77
test samples.

The test set is not used during training. Checkpoint selection relies
on validation rather than test performance. The three lettuce
autolabel datasets contain the same 762 images as \texttt{Data}, in the
same order, and the three autolabel projects use a split file identical
to that of the manual model. The 77 test images are therefore the same
physical images for all four lettuce networks, and none of them belongs
to the 609 training images of any of these networks. For the general
binary configuration, the 77 lettuce test images were removed from
\texttt{Data\_allPlantsSAM2} before splitting; the remaining 1882 of 1959
image--mask pairs were split 80/10/10.

The split is random at the level of individual images: no test image is
used for training, but each lettuce folder, which corresponds to one
acquisition video recorded along a different path, contributes images to
both the training and the test split. The test images therefore show paths
whose other images were seen during training. The reported IoU values may
overestimate performance on paths or fields not seen during training. This
limitation applies to all networks of the comparison.

The realistic scenario uses only the test images from \texttt{insalata\_grande1}, \texttt{insalata\_grande2}, and \texttt{insalata\_media1}: 42 of the 77 test images. These folders were recorded between parallel rows, in the area where the robot operates, from viewpoints the robot can reach. The other five folders were recorded from viewpoints the robot cannot reach and can show more than one path, while the manual masks label only the path the robot should follow. The realistic scenario is therefore a subset of the test split, not a separate test set, and its results describe only the robot's operating conditions.

\section{Architecture comparison: FCN, DeepLabV3, and LR-ASPP}
\label{sec:c5_architecture_comparison}

This comparison addresses the architecture choice before changing the
annotation procedure or crop coverage. FCN, DeepLabV3, and LR-ASPP were
trained and evaluated using the manually annotated lettuce dataset.

\subsection{Model selection and pretrained weights}
\label{subsec:c5_model_selection}

FCN, DeepLabV3, and LR-ASPP were chosen from the implementations available
in TorchVision. All three were trained on the manually annotated lettuce
dataset. Their selection was practical, rather than the outcome of a
comparison with every available architecture.

The implementation separates each network into a backbone, which extracts
image features, and a segmentation head, which produces class scores at
each output location. Transfer learning is implemented by loading
pretrained parameters and adapting the output layers to the target
labeling task, rather than initializing every network parameter from
scratch.

For FCN and DeepLabV3, the selected implementations use a ResNet-50
backbone with pretrained segmentation weights. After these weights
are loaded, the final convolution of the main classifier is replaced by
a new $1\times1$ convolution with one output channel per target class.

LR-ASPP is initialized differently. The implementation uses a
MobileNetV3-Large backbone and requests its default pretrained weights
through the \texttt{weights\_\allowbreak backbone} argument. However, the
\texttt{weights} argument of the complete segmentation model is set to
\texttt{None}. Consequently, the backbone is pretrained, whereas the
LR-ASPP segmentation head is newly initialized for the requested number
of classes.

This distinction is relevant to the interpretation of the model
comparison. The three configurations differ not only in architecture,
but also in the extent of their pretrained initialization: FCN and
DeepLabV3 retain pretrained segmentation-head layers, whereas LR-ASPP
starts with a new segmentation head.

\subsection{Training configuration and loss formulation}
\label{subsec:c5_training_config}

The optimization pipeline is designed to address class imbalance, memory constraints, and the two-stage transfer learning schedule across all evaluated architectures.

\subsubsection{Loss function and class weighting}
Agricultural scenes exhibit a strong pixel imbalance between the navigable soil corridor, the plant canopy, and background areas. To prevent the optimization from biasing toward dominant categories, the models are trained using a weighted multi-class cross-entropy loss:
\begin{equation}
    \mathcal{L}_{\text{WCE}}(Y^*, p) = -\frac{1}{\sum_{i=1}^{H}\sum_{j=1}^{W} w_{Y^*_{i,j}}} \sum_{i=1}^{H} \sum_{j=1}^{W} w_{Y^*_{i,j}} \log(p_{i,j, Y^*_{i,j}}),
    \label{eq:weighted_ce}
\end{equation}
where $Y^*_{i,j} \in \{0, \dots, C-1\}$ is the ground-truth class of pixel $(i,j)$, and $w_c$ is the penalty weight assigned to category $c$.

Class weights are computed exclusively on the training split $\mathcal{D}_{\text{train}}$ to avoid information leakage from validation and test partitions. For each class $c$, the total pixel count $N_c = \sum_{k \in \mathcal{D}_{\text{train}}} \sum_{i,j} \mathbb{I}(Y^{(k)}_{i,j} = c)$ is accumulated across all training masks. The balanced inverse frequency $\text{inv}_c$ is then normalized by the mean of all inverse frequencies:
\begin{equation}
    \text{inv}_c = \frac{\sum_{k=0}^{C-1} N_k}{C \cdot N_c}, \qquad w_c = \frac{\text{inv}_c}{\frac{1}{C}\sum_{k=0}^{C-1} \text{inv}_k}.
    \label{eq:class_weights_norm}
\end{equation}
This normalization enforces $\frac{1}{C} \sum_{c=0}^{C-1} w_c = 1.0$.

For FCN and DeepLabV3, which incorporate an auxiliary classifier on the \texttt{layer3} features (output stride 8 in the dilated TorchVision backbone), the total training objective combines the primary and auxiliary losses with an auxiliary weighting factor of $0.4$:
\begin{equation}
    \mathcal{L}_{\text{total}} = \mathcal{L}_{\text{WCE}}(\text{main}) + 0.4 \cdot \mathcal{L}_{\text{WCE}}(\text{aux}).
    \label{eq:total_training_loss}
\end{equation}
For LR-ASPP, which lacks an auxiliary head, training relies solely on the primary loss $\mathcal{L}_{\text{WCE}}(\text{main})$.

\subsubsection{Data augmentation and two-stage optimization}
Data augmentation is applied exclusively to the training subset (\texttt{full\_\allowbreak train\_\allowbreak dataset}), incorporating random horizontal flips, scaling, and photometric adjustments to handle variable outdoor illumination. The validation and test sets (\texttt{full\_\allowbreak eval\_\allowbreak dataset}) use deterministic resizing without perturbations to preserve ground-truth geometry for objective evaluation.

Due to memory constraints imposed by high-resolution feature maps, models are trained with a batch size of 2 and \texttt{drop\_last=True} to prevent single-sample batches from destabilizing batch normalization layers.

Optimization proceeds across $200$ epochs in two distinct phases:
\begin{enumerate}
    \item \textbf{Stage 1 (Warmup, Epochs 1--10):} Backbone parameters are frozen by setting \texttt{requires\_grad = False}. Only the segmentation heads (and auxiliary classifiers when present) are optimized using AdamW with an initial learning rate of $10^{-3}$ and weight decay of $10^{-4}$. A cosine-annealing scheduler steps each epoch down to $\eta_{\text{min}} = 10^{-6}$. This phase prevents the newly initialized output layers from perturbing the pretrained backbone features with large early gradients.
    \item \textbf{Stage 2 (Differential Fine-Tuning, Epochs 11--200):} At epoch 10, the backbone is unfrozen. A new AdamW optimizer is instantiated with decoupled parameter groups: the backbone is assigned a learning rate of $10^{-5}$ and the segmentation heads a learning rate of $10^{-4}$. The cosine-annealing scheduler is re-initialized across the remaining 190 epochs ($T_{\text{max}} = 190, \eta_{\text{min}} = 10^{-6}$).
\end{enumerate}

Early stopping was intentionally disabled to give models with a newly initialized head (such as LR-ASPP) a sufficient training horizon. Model checkpoints are evaluated after each epoch on the unaugmented validation set; \texttt{best.pth} is saved whenever the validation loss decreases below its historical minimum, and \texttt{last.pth} records the final epoch state.

\subsection{Selection of LR-ASPP}
\label{subsec:c5_lraspp_selection}

LR-ASPP was adopted because the substantial reduction in recorded
inference time justified accepting an mIoU approximately 1.2 percentage
points below the other two configurations. It was not the most accurate
model, but offered the practical accuracy--latency compromise sought for
robot perception. FCN and DeepLabV3 had higher IoU but substantially
longer recorded inference times. The subsequent SAM-supervised training
runs therefore used LR-ASPP while varying the output label set.

Two limitations apply to this comparison. First, the metrics are computed
on the validation split, which is also used to select \texttt{best.pth}
through the minimum validation loss, so they are optimistic for all three
networks. Second, recorded inference times depend on the conditions of each
run: in the evaluation scripts of Section~\ref{sec:c5_supervision_comparison},
the same LR-ASPP checkpoint records mean times between 0.010~s and 3.67~s per
image. The 5.60-fold and 8.35-fold ratios are meaningful only if the three
exports were produced under identical conditions.

This choice is based on the available offline comparison. The records
do not establish a hardware-independent speed ranking or demonstrate
that the integrated robot meets its control timing requirements.
Those requirements must be assessed using the deployed model and the
complete perception and control pipeline.

Manual masks from \texttt{Data} supply the ground truth for all comparative evaluations. The evaluation measures the generalization capability of the trained networks rather than the static quality of the raw SAM~3 masks. Specifically, no direct pixel-level comparison is performed between uncurated SAM~3 masks and manual annotations; instead, each trained LR-ASPP network executes forward inference in evaluation mode (\texttt{eval()}), computing the discrete predicted class map via:
\begin{equation}
    \hat{Y}_{i,j} = \arg\max_{c \in \{0,\dots,C-1\}} P(Y_{i,j} = c \mid I),
    \label{eq:inference_argmax}
\end{equation}
which is subsequently compared against the human ground-truth mask.

Evaluation uses the Intersection over Union (IoU) metric:
\begin{equation}
    \text{IoU}_c = \frac{\text{TP}_c}{\text{TP}_c + \text{FP}_c + \text{FN}_c},
    \label{eq:eval_iou}
\end{equation}
where $\text{TP}_c$, $\text{FP}_c$, and $\text{FN}_c$ denote true positives, false positives, and false negatives for class $c$, respectively. Mean IoU (mIoU) denotes the arithmetic mean across all evaluated classes, including background where applicable.

Performance is evaluated across two distinct subsets of the 77-image test partition (split indices from \texttt{split\_indices.pth}):
\begin{itemize}
    \item \textbf{Complete test set (77 images):} Spans all eight lettuce acquisition folders (\texttt{insalata\_\allowbreak grande1}, \texttt{insalata\_\allowbreak grande2}, \texttt{insalata\_\allowbreak media1}, \texttt{insalata\_\allowbreak media2}, \texttt{insalata\_\allowbreak media3}, \texttt{insalata\_\allowbreak piccola}, \texttt{insalata\_\allowbreak piccola\_1}, and \texttt{insalata\_\allowbreak piccola\_2}), including viewpoints that the robot cannot reach.
    \item \textbf{Realistic operational scenario (42 images):} Restricts evaluation to \texttt{insalata\_\allowbreak grande1}, \texttt{insalata\_\allowbreak grande2}, and \texttt{insalata\_\allowbreak media1}. These images were taken between parallel rows, in the area where the robot is meant to operate. Models were not retrained on this subset; they were trained on their respective full datasets and evaluated post-hoc on these operational images.
\end{itemize}

The results support the following conclusions:
\begin{enumerate}
    \item \textbf{The manual model is the best overall.} It has the highest IoU in every comparison, with path IoU 0.9566 on the complete test set and 0.9615 in the realistic scenario.
    \item \textbf{Lettuce-only autolabel training.} In the realistic scenario, the binary network trained only on lettuce reaches a path IoU of 0.9013, 6.0 percentage points below the manual model. The three lettuce autolabel networks differ by less than 0.5 percentage points on path IoU in this scenario (0.8966--0.9013), and on the complete test set the binary network is the lowest of the three (0.3917 against 0.4124). These data do not show that removing the plant and covering classes improves path segmentation.
    \item \textbf{General autolabel data.} The general binary network reaches a path IoU of 0.9071 in the realistic scenario, close to the lettuce binary network (0.9013), and 0.6369 on the complete test set, against 0.3917. Its training data differ in several ways at once (tomato and cucumber images, a different set of lettuce frames, and the \texttt{central path} prompt), so the improvement cannot be attributed to one factor.
    \item \textbf{Complete test set versus realistic scenario.} Both scenarios evaluate the same networks, trained on all eight lettuce folders; the realistic scenario is only a subset of the test images. All autolabel networks lose much of their path accuracy on the complete test set (path IoU 0.39--0.41 for the lettuce networks and 0.64 for the general network), while the manual model does not (0.9566). The drop comes from the five folders outside the operational scenario. Their images were taken from viewpoints the robot cannot reach and can show several paths: the manual masks label only the path the robot should follow, whereas the autolabel networks segment every visible path, and the IoU counts the additional paths as false positives. In addition, visual inspection showed that SAM~3 produced less accurate path masks in images taken from unusual viewpoints or where the path between the rows is not clearly visible, so the networks were trained on noisier labels for these conditions. The complete-test values therefore combine segmentation errors, label noise, and this difference in label definition; the three effects were not separated quantitatively.
    \item \textbf{Full semantic segmentation.} With an mIoU of 0.5925 in the realistic scenario, the 4-class autolabel network does not support replacing manual annotation when all four classes are required.
    \item \textbf{Sufficiency for navigation.} Path IoU values of 0.9013 (lettuce binary) and 0.9071 (general binary) in the realistic scenario imply that more than 90\% of the ground-truth path pixels are predicted as path, since recall $\text{TP}/(\text{TP}+\text{FN})$ is never lower than IoU. Whether this accuracy is sufficient for row following depends on how the residual errors are distributed along the corridor boundaries. It must be established through an application threshold or a downstream test of the path extraction and controller (Chapters~\ref{cap:geometric_reference} and~\ref{cap:experiments}), not from IoU alone.
\end{enumerate}


\subsection{Network deployed on the robot}
\label{subsec:c5_deployed_network}

After the lettuce study, the binary labeling was extended to the complete image collection, labeled entirely by SAM~3 with the \texttt{central path} prompt and without manual correction (\texttt{Data\_allPlantsSAM2}). The binary LR-ASPP network trained on this collection (checkpoint \texttt{best\_allsam2.pth}, epoch 25) is the network used on the robot in Chapters~\ref{cap:platform} and~\ref{cap:experiments}. Its training data include the lettuce test images, so its own IoU on them would not be an independent measure and is not reported. The general network of Table~\ref{tab:c5_results_binary_general}, trained with the same labels on the collection without those images, gives the independent estimate for this configuration: path IoU 0.9071 in the realistic scenario and 0.6369 on the complete test set. It is a separate training run (best epoch 27 instead of 25), so the estimate refers to the configuration rather than to the exact deployed weights. The deployed network was also assessed qualitatively, by visual inspection of its predictions over the dataset, and then in simulation and in field tests (Chapter~\ref{cap:experiments}). The visual inspection also showed that it segments adjacent or non-traversable corridors, which the manual lettuce masks leave as background. The checkpoint documentation identifies \texttt{Data\_allPlantsSAM2} as its training set, whereas the historical training script refers to \texttt{Data\_allPlantsMIX}; the checkpoint does not store the dataset path.

For integration with the geometric extraction, a binary network outputs the path class directly. The extractor \texttt{pf4.py} receives the predicted class map and a \texttt{path\_class} parameter (default 1) and binarizes the map internally, so a multi-class output could also be used by setting \texttt{path\_class} to the index of its path class. It uses only the path class: it analyzes 24 horizontal strips and fits the left and right corridor edges with iteratively reweighted least squares (Chapter~\ref{cap:geometric_reference}).
